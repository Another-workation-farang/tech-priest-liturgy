[I] INITIALIZATION SEQUENCE

--------------------------------------------------------------------------------

>> MACHINE SPIRIT COMMUNION...                       [ATTENDING]

LITURGY IS A SUPERSET OF PYTHON. A .lit FILE TOKENIZES, HAS ITS RITUAL KEYWORDS SUBSTITUTED BACK TO THEIR PYTHON SPELLINGS, AND COMPILES EXACTLY AS A .py FILE WOULD. UNDERNEATH IT IS PYTHON — THE SAME OBJECTS, THE SAME SCOPING, THE SAME STANDARD LIBRARY.

THE SUPERSET PROMISE: ALL VALID PYTHON IS VALID LITURGY, EXCEPT PROGRAMS THAT USE A LITURGY WORD AS AN IDENTIFIER. SUBSTITUTION RUNS ONE DIRECTION ONLY — print AND def STILL WORK INSIDE A .lit FILE.

$ liturgy commune

++ cogitator 3.14.7 attends your litanies ++

--------------------------------------------------------------------------------

EVERY ONE OF PYTHON'S 35 KEYWORDS PLUS 3 SOFT KEYWORDS BEARS A RITUAL SPELLING. THE TABLE IS EXHAUSTIVE. A TEST ITERATES THE LIVE keyword.kwlist ON EVERY RUN SO AN UNTHEMED KEYWORD FAILS THE SUITE LOUDLY. EXCERPT FOLLOWS; THE FULL LEXICON RESIDES IN THE LIBER.

THREE EXEMPTIONS PROTECT CODE YOU DO NOT CONTROL: A WORD AFTER . IS NEVER SUBSTITUTED; A WORD IN KEYWORD-ARGUMENT POSITION IS NEVER SUBSTITUTED; INSIDE import STATEMENTS ONLY THE STATEMENT'S OWN KEYWORDS ARE TOUCHED. THUS template.render() REMAINS ITSELF AND IS NOT MANGLED INTO template.return().

[III] THE GREATER RITES — CONSTRUCTS

--------------------------------------------------------------------------------

THREE CONSTRUCTS PYTHON CANNOT EXPRESS. EACH DESUGARS INTO SELF-CONTAINED GENERATED PYTHON — NOTHING IS IMPORTED FROM LITURGY AT RUNTIME. A FOURTH, noospheric, WAS CUT RATHER THAN BEND THAT RULE.

.. construct:: consecrated NAME: ARCHETYPE = VALUE
   A BINDING THAT MAY NOT BE REBOUND. PYTHON HAS NO CONSTANTS, ONLY THE
   ALL-CAPS HONOUR SYSTEM. REBINDING IS REJECTED AT COMPILE TIME WITHIN THE
   DECLARING SCOPE, AS IS A SECOND CONSECRATION OF THE SAME NAME AND ONE
   PLACED INSIDE A LOOP.
   :archetype: REQUIRED, PER SECTION [VIII]. NEWLY EXPRESSIBLE: THE CONSTRUCT
               USED TO REACH THE COMPILER THROUGH THE ANNOTATION SLOT, SO A
               CONSECRATED NAME COULD NOT CARRY ONE AT ALL.
   :limit: WHAT THE COMPILER CANNOT SEE IT CANNOT STOP — setattr, globals(),
             ASSIGNMENT THROUGH THE MODULE OBJECT AND exec ALL PASS.
             THIS IS ENFORCEMENT, NOT A GUARANTEE.

.. construct:: litany(ATTEMPTS, resting=SECONDS, curse=EXCEPTION):
   A BLOCK RE-CHANTED ON NAMED FAILURES. THE FIRST ARGUMENT IS TOTAL
   ATTEMPTS, NOT RETRIES, AND IS EVALUATED EXACTLY ONCE.
   :curse: REQUIRED AND KEYWORD-ONLY, SPELLED OUT — NOT PASSED THROUGH **.
           NOTHING IS CAUGHT IMPLICITLY — A RETRY
           THAT CATCHES EVERYTHING WOULD RE-ATTEMPT A PatternMismatch.
   :resting: OPTIONAL. OMITTED, NO TIMING CODE IS EMITTED AT ALL. EVALUATED
             ONCE, LIKE THE COUNT, AND A NEGATIVE VALUE IS REJECTED BEFORE
             THE FIRST ATTEMPT.
   :forbidden: cease AND persist AT THE LITANY'S OWN LEVEL — THEY WOULD BIND
               TO THE INVISIBLE RETRY LOOP. INSIDE A REAL LOOP IN THE BODY
               THEY ARE THE AUTHOR'S OWN AND PASS UNTOUCHED.

.. construct:: augur:
   CONDITIONS READ BEFORE A RITE'S BODY RUNS, ONE PER LINE BENEATH A BARE
   augur:, VALID ONLY AT THE OPENING OF A RITE. A CONTRACT, NOT AN
   ASSERTION — IT DESUGARS TO A REAL if/raise AND SURVIVES python -O. A
   STATEMENT, A CONSTANT OR A WALRUS IN THE BLOCK IS REJECTED AT COMPILE
   TIME; A CALL IS A CONDITION, JUDGED BY ITS TRUTH.
   :raises ImpureOffering: WITH THE LITURGY SOURCE OF THE FAILED
                           CONDITION QUOTED, NOT THE GENERATED PYTHON.

.. function:: liturgy.loader.chant(path: str, argv: list[str]) -> int

   EXECUTES A .LIT FILE WITH __main__ SEMANTICS, AS python file.py EXECUTES
   A PYTHON ONE. THE PATH IS RESOLVED ABSOLUTE BEFORE THE RITE BEGINS.

   :param path: THE VECTOR OF THE LITANY TO BE CHANTED.
   :param argv: ARGUMENTS PASSED THROUGH TO THE PRAYER AS sys.argv[1:].
   :returns: PROCESS EXIT CODE. ZERO SIGNIFIES THE OMNISSIAH IS SERVED.
   :raises MachineCurse: ANY UNHANDLED EXCEPTION, RENDERED AS A CURSE.
.. function:: liturgy.loader.install() -> None

   REGISTERS THE IMPORT HOOK ON sys.path_hooks, CARRYING THE DEFAULT
   LOADER DETAILS ALONGSIDE. THEREAFTER LITURGY MAY
   IMPORT PYTHON, AND PYTHON MAY IMPORT LITURGY. IDEMPOTENT.

   :called by: chant, commune AND prove — AND NOTHING ELSE. AN INTERPRETER
               STARTED ANY OTHER WAY CANNOT SEE A .LIT AT ALL.
   :environment-wide: A .pth IN site-packages RUNS IT AT INTERPRETER
                      START, SO ANY PYTHON PROCESS CAN IMPORT A LITANY:
                      import liturgy.loader; liturgy.loader.install()
                      COSTS ~10-20ms PER START, WRITES INTO site-packages
                      (USE A VENV), AND BUYS IMPORTING BUT NOT COLLECTION —
                      PLAIN PYTEST STILL FINDS NO TRIALS IN A test_*.lit.
                      DELETE THE FILE TO UNDO IT.
.. function:: liturgy.curse.render_curse(exc_type, exc, tb, *, file=None) -> None

   PRINTS A MACHINE CURSE IN PLACE OF A PYTHON TRACEBACK. FRAMES FROM THE
   LAUNCHER MACHINERY ARE DROPPED; ONLY .LIT FRAMES RECEIVE THE TREATMENT.
   LINE AND CARET POSITION ARE EXACT — A COLUMN-LEVEL SOURCE MAP FROM THE
   TOKEN PASS GUARANTEES IT, THOUGH render AND return DIFFER IN LENGTH.

   :override: --profane OR LITURGY_PROFANE=1 RESTORES THE MUNDANE TRACEBACK.
.. function:: liturgy.heresy.rebuke(alias: str, proper: str, *, stream=None) -> None

   LOGS AND REBUKES AN INVOCATION BY MUNDANE ALIAS (run, repl). THE REBUKE
   ESCALATES ACROSS INVOCATIONS AND SATURATES AT THE THIRD.

   :state: $XDG_STATE_HOME/liturgy/heresies.json — THE PERMANENT RECORD.
   :absolution: --absolved FOR ONE INVOCATION; LITURGY_PIOUS=0 EVERYWHERE.
CODE REFERENCE — examples/fibonacci.lit:
## The Rite of Recurrent Numeration
## Chanted before the cogitator, that it may recall the sacred sequence.

rite fibonacci(n: int) -> int:
    should n < 2:
        render n
    render fibonacci(n - 1) + fibonacci(n - 2)


rite litany_of_numeration(count: int) -> Void:
    recited = []
    foreach i among span(count):
        value = fibonacci(i)
        recited.append(value)
        intone(f"++ fibonacci({i}) is {value} ++")
    intone(f"++ {measure(recited)} numbers recited ++")


should __name__ == "__main__":
    litany_of_numeration(11)

[VII] THE READING OF OMENS — TOOLING VERBS

--------------------------------------------------------------------------------

SEVEN TOOLING VERBS ARE BUILT. augur READS A LITANY, transcribe WRITES ONE, forge COMPILES ONE WITHOUT CHANTING IT, consecrate CHECKS THE SEALS ACROSS ALL OF THEM, sanctify SETS ONE'S FORM IN ORDER, prove RUNS THE TRIALS, AND purge CLEARS WHAT CHANTING LEFT BEHIND. ONE NAME — anoint — REMAINS RESERVED AND UNBUILT.

.. function:: liturgy augur PATH... [--plain]

   READS .LIT AND .PY FILES FOR FAULTS WITHOUT CHANTING THEM. A DIRECTORY IS
   WALKED, PRUNING DOT-DIRECTORIES, __pycache__ AND VIRTUAL ENVIRONMENTS
   (ANYTHING HOLDING A pyvenv.cfg); A DIRECTORY NAMED DIRECTLY IS ALWAYS
   READ, AND OVERLAPPING ARGUMENTS REPORT EACH FINDING ONCE. EXACTLY TWO
   CHECKS, AND NO THIRD: BINDINGS WHOSE NAME IS ONE OF THE SIXTY WORDS THAT
   BECOME ANOTHER WORD (THE MACHINE'S OWN CARRIER NAMES INCLUDED), AND —
   FOR A .LIT FILE — THAT IT
   COMPILES, SO augur AND chant CANNOT DISAGREE. IT IS NOT A GENERAL LINTER
   AND WILL NOT BECOME ONE.

   :param PATH: FILES OR DIRECTORIES TO BE READ.
   :option --plain: ONE file:line:col: LINE PER FINDING, FOR EDITORS AND CI.
   :returns: 0 IF NOTHING WAS REPORTED, 1 IF ANYTHING WAS.
   :silently: A FINDING SO MARKED SUBSTITUTES TO A NAME, NOT A KEYWORD —
              THE FILE COMPILES AND THE HARM IS DEFERRED.
   :not checked: THE FOUR CONSTRUCT WORDS. THEY ARE NEVER SUBSTITUTED, SO
                 NOTHING BOUND TO ONE QUIETLY CHANGES MEANING. consecrated AND
                 unsanctioned ARE STILL CAUGHT, BY THE COMPILE CHECK — AS IS
                 AN UNDECLARED ARCHETYPE.
   :unscanned: A DIRECTORY REACHED BY SYMLINK IS NAMED, NOT PASSED OVER.
$ liturgy augur --plain quiet.lit
quiet.lit:1:1: span is reserved; it becomes range -- silently
$ liturgy augur --plain imp.lit
imp.lit:1:33: render is reserved; it becomes return

THE SECOND IS THE SUBTLE ONE. THE THIRD PROHIBITION LEAVES AN INVOCATION'S TARGETS UNSUBSTITUTED, SO within json invoke loads styled render GENUINELY BINDS THE NAME render, AND EVERY LATER MENTION OF IT BECOMES return. THE EXEMPTIONS GOVERN WHAT IS SUBSTITUTED. THEY SAY NOTHING ABOUT WHAT IS SAFE TO BE BOUND TO.

.. function:: liturgy transcribe SOURCE [-o DEST]

   RENDERS A PYTHON FILE INTO LITURGY. PRINTS TO STDOUT UNLESS -o IS GIVEN.
   LINE ENDINGS AND THE SOURCE'S DECLARED ENCODING ARE CARRIED THROUGH; THE
   OUTPUT DIFFERS FROM ITS SOURCE IN ITS WORDS AND IN NOTHING ELSE.

   :self-check: THE OUTPUT IS TRANSFORMED BACK TO PYTHON AND COMPARED AGAINST
               THE SOURCE BEFORE ANYTHING IS WRITTEN. A DESTINATION FILE GETS
               A SECOND, BYTE-LEVEL CHECK IN ITS OWN DECLARED ENCODING.
   :refuses: A SOURCE THAT WILL NOT PARSE, ONE THAT CANNOT BE DECODED, ONE
             BINDING A RESERVED NAME, AND ITS OWN OUTPUT IF IT DOES NOT
             ROUND-TRIP OR WOULD NOT CHANT — THE OUTPUT IS COMPILED BEFORE
             ANYTHING IS WRITTEN. THE COLLISION RULE IS augur'S, FROM THE
             SAME CODE.
   :returns: 0 IF WRITTEN, 1 IF REFUSED.
$ liturgy transcribe greet.py -o greet.lit
++ 8 lines transcribed ++
$ liturgy transcribe shadow.py
++ CANNOT TRANSCRIBE: 1 COLLISION ++
  shadow.py:1  span         -> reserved (range)
rename these, then chant again

.. function:: liturgy forge [PATH...] [--anew]

   COMPILES .LIT FILES TO BYTECODE AHEAD OF THE IMPORT THAT WOULD OTHERWISE
   DO IT. WITH NO PATHS, WALKS THE WORKING DIRECTORY. .PY IS LEFT TO
   compileall. THE COMPILE RUNS THROUGH THE IMPORT SYSTEM'S OWN get_code, SO
   THE BYTECODE IS BYTE-FOR-BYTE WHAT AN IMPORT WOULD HAVE PRODUCED.

   :option --anew: FORGE EVEN LITANIES WHOSE BYTECODE IS ALREADY CURRENT.
   :does not chant: IT COMPILES WITHOUT EXECUTING. THAT IS THE WHOLE
                     DIFFERENCE BETWEEN FORGING A LITANY AND IMPORTING ONE.
   :cache: ORDINARY .pyc UNDER __pycache__, NOT A .litc OF OUR OWN —
           get_code REACHES FOR cache_from_source AS A MODULE-LEVEL FUNCTION,
           SO A SUBCLASS CANNOT REDIRECT IT, AND THE EXTENSION IS NOT WORTH
           FORKING THE IMPORT MACHINERY FOR.
   :refuses: UNDER -B OR PYTHONDONTWRITEBYTECODE, WHERE EVERY WRITE WOULD
             BE A SILENT NO-OP AND SUCCESS WOULD BE A LIE.
   :returns: 0 IF ALL WERE FORGED OR ALREADY CURRENT, 1 OTHERWISE.
$ liturgy forge
   forged mod.lit
   forged sub/two.lit
++ 2 litanies forged ++

A SECOND RUN REPORTS RATHER THAN REPEATS. THE DISTINCTION IS MEASURED, NOT GUESSED — THE CACHE FILE'S TIMESTAMP IS READ EITHER SIDE OF THE COMPILE, AND ONLY A CHANGE TO IT COUNTS AS A FORGING:

$ liturgy forge
++ 0 litanies forged, 2 already current ++

.. function:: liturgy consecrate [PATH...] [--plain]

   CHECKS EVERY MODULE-LEVEL consecrated NAME AGAINST THE WHOLE TREE. WALKS
   TWICE — ONCE TO LEARN WHAT IS SEALED, ONCE TO FIND WHAT REACHES A SEAL.
   READS THREE SHAPES: ASSIGNMENT THROUGH THE MODULE OBJECT, setattr WITH A
   LITERAL NAME, AND DELETION. A .PY FILE COUNTS AS MUCH AS A LITANY.

   :option --plain: EMIT file:line:col: LINES AND NOTHING ELSE.
   :not enforcement: A REPORT. NOTHING HERE STOPS A REBINDING AT RUN TIME.
   :cannot see: globals()["PORT"] = 9, AND setattr WITH A COMPUTED NAME.
                 THE LITERAL FORM IS READ; THE COMPUTED FORM IS NOT GUESSED AT.
   :scope: MODULE-LEVEL SEALS ONLY — A consecrated INSIDE A RITE IS NOT
           REACHABLE AS module.NAME. MODULES MATCH BY BASENAME, AND A SHARED
           BASENAME IS CALLED OUT RATHER THAN REPORTED ON CONFIDENTLY.
   :returns: 0 IF EVERY SEAL HELD, 1 IF ANY WAS REACHED OR ANY LITANY
             COULD NOT BE READ.
$ liturgy consecrate
++ THE SEAL IS BROKEN ++
   config.lit, line 1
       consecrated PORT = 8080
                   ^^^^
   PORT is consecrated here, and reached in:
     assigned  server.lit:4

++ 1 seal broken, 1 held ++

.. function:: liturgy sanctify [PATH...] [--check]

   RESHAPES THE WHITESPACE BETWEEN A LITANY'S TOKENS AND NOTHING ELSE.
   INDENTATION TO FOUR SPACES PER LEVEL, TRAILING WHITESPACE GONE, BLANK
   RUNS CAPPED AT TWO, ONE FINAL NEWLINE. .LIT ONLY — RUFF AND BLACK CANNOT
   READ A LITANY, WHICH IS WHY THIS EXISTS.

   :option --check: REPORT WHAT IS UNCLEAN AND WRITE NOTHING; EXIT 1
                    IF ANY LITANY WOULD CHANGE.
   :does not use ast.unparse: IT WOULD REFORMAT EVERYTHING AND DROP
                               EVERY COMMENT. NO EXPRESSION IS RE-FLOWED,
                               NO STRING RE-QUOTED, NO TOKEN MOVED.
   :left alone: A MULTI-LINE STRING'S INTERIOR; A BRACKET CONTINUATION;
                A STANDALONE COMMENT BEFORE A BLOCK'S FIRST STATEMENT,
                WHICH tokenize REPORTS BEFORE THE INDENT AND A NAIVE
                FORMATTER WALKS OUT OF ITS BLOCK.
   :guarantee: THE SIGNIFICANT TOKEN STREAM AND THE COMPILED AST MUST
               MATCH BEFORE AND AFTER, OR THE FILE IS LEFT AS IT WAS.
   :returns: 0 DONE, 1 REFUSED — OR, UNDER --check, 1 IF UNCLEAN.
$ liturgy sanctify
   sanctified prayer.lit
++ 1 sanctified, 0 already in order ++

.. function:: liturgy prove [ARG...]

   RUNS PYTEST WITH THE .LIT IMPORT HOOK INSTALLED AND test_*.lit COLLECTED.
   EVERY ARGUMENT IS PASSED STRAIGHT THROUGH — PATHS, -k, -x, -v. FAILURES
   QUOTE LITURGY AT THE LITANY'S OWN LINE NUMBER.

   :requires: PYTEST, AN OPTIONAL EXTRA — pip install 'liturgy[trials]'.
              WITHOUT IT THE VERB REFUSES RATHER THAN TRACEBACKING.
   :convenience only: A conftest.py CALLING install() AND ADDING A
                       pytest_collect_file FOR test_*.lit DOES THE SAME.
                       THE VERB SUPPLIES IT AS A PLUGIN SO NO PROJECT
                       NEEDS THE BOILERPLATE.
   :limitation: PYTEST'S ASSERTION REWRITING DOES NOT APPLY TO A LITANY.
                A FAILED attest REPORTS AssertionError AND THE SOURCE LINE,
                NOT THE OPERANDS.
   :returns: PYTEST'S OWN EXIT CODE, UNFLATTENED — 0 PASSED, 1 FAILURES,
             5 NOTHING COLLECTED.
$ liturgy prove -q -k pleased
.                                                                        [100%]
1 passed, 1 deselected in 0.00s

.. function:: liturgy purge [--heresies]

   REMOVES EVERY __pycache__ BENEATH THE WORKING DIRECTORY. SYMLINKED
   DIRECTORIES ARE NEVER ENTERED. EACH REMOVAL IS NAMED ONLY AFTER THE DELETE
   BENEATH IT HAS SUCCEEDED, SO THE REPORT NEVER CLAIMS A DELETION THAT DID
   NOT HAPPEN.

   :option --heresies: ALSO CLEAR THE HERESY RECORD OF SECTION [VI].
   :guard: THE ONLY DESTRUCTIVE VERB. IT REFUSES OUTRIGHT UNLESS THE TREE
           HOLDS AT LEAST ONE .LIT FILE — A RECURSIVE DELETE LAUNCHED FROM
           THE WRONG DIRECTORY IS A BAD AFTERNOON.
   :on failure: A RELIC THAT WILL NOT GO IS REPORTED AND STEPPED OVER, NOT
                RAISED. ONE UNREADABLE CACHE MUST NOT STRAND THE REST.
   :returns: 0 IF ALL WENT, 1 IF THE GUARD REFUSED OR ANY REMOVAL FAILED.
$ liturgy purge
++ 0 relics purged ++

EACH REMOVAL PRINTS AS purged <ABSOLUTE PATH> ON ITS OWN LINE, AND THE RUN ENDS WITH THE COUNT ABOVE. FROM A TREE HOLDING NO LITANY, THE GUARD SPEAKS INSTEAD AND NOTHING IS TOUCHED:

   no .lit file found; refusing to delete anything

[VIII] THE DECLARATION OF ARCHETYPES

--------------------------------------------------------------------------------

PYTHON INVITES TYPE HINTS AND ENFORCES NOTHING. LITURGY ENFORCES THEM AT COMPILE TIME. ONE NEW WORD — unsanctioned — AND IT IS THE WORD FOR REFUSING THE RULE. archetype WAS ALREADY type, SO THE ANNOTATION ITSELF GAINED NO SPELLING OF ITS OWN.

.. rule:: every parameter, every return, every consecrated binding

   A LITANY MUST DECLARE THE ARCHETYPE OF EVERY RITE'S PARAMETERS, OF EVERY
   RITE'S RETURN, AND OF EVERY consecrated BINDING. -> Void IS THE IDIOM FOR
   A RITE THAT RENDERS NOTHING. EVERY PARAMETER POSITION PYTHON CAN ANNOTATE
   IS COVERED: POSITIONAL-ONLY, ORDINARY, KEYWORD-ONLY, *args AND **kwargs.

   :presence, not correctness: LITURGY SEES THAT AN ANNOTATION IS WRITTEN.
                               IT CANNOT SEE WHETHER IT IS TRUE.
                               rite count(n: str) -> int: IS A LIE IN BOTH
                               HALVES AND PASSES. A TYPE CHECKER IS DESIGNED
                               AND UNSCHEDULED.
   :not required: PLAIN ASSIGNMENTS, foreach TARGETS, COMPREHENSION
                  VARIABLES, anointed ... styled TARGETS, THE NAME A curse
                  BINDS. IDIOMATIC PYTHON LEAVES THEM BARE AND SO DOES THIS.
   :exempt by construction: self AND cls IN THE FIRST PARAMETER SLOT ONLY;
                            servitor ENTIRELY, SINCE PYTHON CANNOT ANNOTATE A
                            LAMBDA'S PARAMETERS; commune, WHERE EVERY ENTRY IS
                            ITS OWN COMPILATION UNIT; AND .py FILES, WHICH ARE
                            PYTHON'S BUSINESS.
   :where it lives: THE COMPILE PATH, BESIDE THE OTHER CONSTRUCT
                    REJECTIONS — SO chant, prove AND augur REPORT IT ALIKE AND
                    CANNOT DISAGREE.
.. construct:: unsanctioned

   THE EXEMPTION SAID ALOUD. A MODIFIER WITH NO PYTHON SPELLING: IT IS
   SPLICED AWAY AND WHAT IT MARKED IS RECORDED BESIDE THE GENERATED SOURCE,
   SO A LITANY USING IT COMPILES TO EXACTLY THE PYTHON IT WOULD HAVE
   WITHOUT IT.

   :before a rite: EXEMPTS THAT RITE, AND EVERYTHING NESTED INSIDE IT.
                   REACHES remote rite TOO.
   :before a consecrated: EXEMPTS THAT ONE BINDING.
   :alone at the margin: EXEMPTS THE WHOLE LITANY. THERE IS NO PER-LINE FORM.
   :anywhere else: A HERESY, NOT A SILENT NO-OP — A MODIFIER THAT LOOKS
                   APPLIED AND IS NOT IS WORSE THAN NO MODIFIER.
   :not the opposite of: Sanctioned, WHICH IS True. A DIFFERENT WORD IN A
                         DIFFERENT CASE MET IN A DIFFERENT POSITION.
rite greet(name: str) -> Void:
    intone(f"Ave {name}")
